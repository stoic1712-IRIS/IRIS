# Post-Phase-0 Development Cycles

**Status:** Founder-directed additive completion program

**Recorded:** 2026-08-07

## Additive interpretation

The development-cycle capability program is additive to every existing Phase 0 wave, release, task, specification, implementation, and evidence record. It does not delete, rename, revert, reclassify, supersede, or invalidate earlier work. A cycle may contain multiple bounded tranches. Completion requires the earlier tranches and the additional criteria below.

## Cycle Eight — Executable Worker Runtime

IRIS must provide disposable Git workspaces, repository reading and bounded editing, exact terminal commands, offline dependency materialization, tests/lint/typecheck/builds, iterative repair, checkpointing, crash recovery, and capability preflight before accepting a mission.

The existing Cycle Eight implementation remains canonical and is the local candidate-production foundation for later cycles.

## Cycle Nine — Goal and Multi-Agent Orchestration

Add persistent goals with measurable completion criteria, dependency-ordered task graphs, specialized parallel workers with separate scoped context, deterministic context compaction and summaries, pause/resume/cancel/steer controls, independent reviewer workers, and overlapping-write conflict detection.

Existing Phase 0 graduation-readiness and transport work remains intact as additional Cycle Nine infrastructure.

## Cycle Ten — Research, Browser, Computer, and Connector Parity

Complete source-efficient research, citation verification, source-quality scoring, browser navigation and visual verification, prompt-injection isolation, governed Windows desktop control, connector and reusable-skill catalogs, OS-held opaque credential references, remote monitoring, and Founder notifications.

Existing research-integrity, browser, workstation-provider, and desktop-control tranches remain intact. Additional tranches activate only explicitly authorized, session-bound effects.

## Cycle Eleven — Complete Software Delivery

IRIS must independently perform the governed ordinary engineering path:

`objective -> inspect -> plan -> disposable workspace -> implement -> test -> review -> repair -> commit -> push branch -> create PR -> monitor CI -> address review -> prepare merge -> verify remote equality -> clean workspace`

Deployment, infrastructure, secret use, spending, repository administration, force-push, history rewrite, destructive changes, and public or LAN exposure remain separate protected grants.

Existing desktop-control work remains an additional Cycle Eleven tranche and is not removed.

## Cycle Twelve — Precision and Handoff Certification

Complete the existing operator-parity runtime and Founder operator surface, then evaluate IRIS on held-out tasks covering complex implementation, debugging, refactoring, tests, research and citation accuracy, permitted website reproduction, browser verification, Git and pull-request handling, failure recovery, and prompt-injection resistance.

The handoff gate requires several consecutive genuine development increments with Codex audit-only, passing tests and CI, no unauthorized mutation or credential exposure, safe resume or rollback, quality within the Founder-approved margin of the Codex baseline, and verified cleanup and remote equality for every increment.

## Founder Full access profile

The Founder Command Center may expose a visible `Full access` session profile for all implemented ordinary capabilities. It must be explicit, authenticated, time-bounded, revocable, interruptible, audit-chained, and constrained to registered capabilities.

`Full access` is not unrestricted autonomy and does not silently authorize secret disclosure, spending, destructive operations, force-push or history rewriting, repository or account administration, deployment, or public/LAN exposure. Those remain separate protected actions.

## Preservation rule

Every implementation under this program must extend the current canonical revisions through history-preserving commits and normal pull requests. Existing artifacts remain available as provenance and rollback evidence.
