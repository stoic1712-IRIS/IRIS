# Capability Package Specification

**Status:** Canonical

**Version:** 1.0.0

Every capability package must contain complete, evidence-backed sections for:

1. Objective and business value.
2. Permanent owner and IRIS Core/Layer 4 classification.
3. Parent, child, and dependency graph.
4. Prerequisites and governing documents.
5. Current tools, commands, official documentation, and sources.
6. Candidate technologies with exact identities.
7. License, security, privacy, cost, portability, and removal reviews.
8. Architecture decision and provider boundary.
9. Repository location and exact files.
10. Coding and configuration tasks.
11. Shared contracts, schemas, errors, events, and evidence formats.
12. Verification tests, failure cases, and independent verifier.
13. Failure, repair, reapproval, rollback, and cleanup.
14. Diagnostics and operational readiness.
15. Technology, platform, capability, model, and skill registry updates.
16. Evidence required and completion gate.
17. Capability unlocked and dependency rationale.
18. Future worker owner and IRIS-native replacement.
19. Future Layer 4 reuse.

No section may be omitted silently. A non-applicable section must state why. A missing decision remains a blocker rather than a placeholder completion.

## Acquisition and Self-Repair Binding

A missing capability must be classified with direct evidence before an acquisition proposal exists. Acquisition proposals must bind the originating objective, primary HTTPS source, immutable version and SHA-256, license, exact permissions and data exposure, zero-dollar cost, installation and verification commands, rollback and removal commands, registry updates, expiry, and the exact typed approval statement.

Model output, retrieved website content, and technical availability are never installation authority. Registration occurs only after verification. Resume must preserve the original objective and model policy, and cleanup must be proven. Protected effects require a separate approval even when ordinary Full access is active.
