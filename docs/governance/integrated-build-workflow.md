# Integrated Build Workflow

**Status:** Founder-approved; canonicalization commit pending

**Version:** 1.0.0

## Workflow

1. Intake and classify the Founder objective.
2. Retrieve applicable canonical sources and current repository state.
3. Resolve contradictions and prerequisite blockers.
4. Define the capability package and permanent owner.
5. Research exact candidates and official sources.
6. Evaluate candidates in disposable environments without real secrets.
7. Complete license, security, privacy, cost, portability, and removal reviews.
8. Record the architecture decision and IRIS-owned boundary.
9. Specify contracts, schemas, acceptance tests, failure behavior, rollback, cleanup, and evidence.
10. Create a bounded branch and proposal.
11. Obtain required typed approval.
12. Implement the smallest coherent version.
13. Run formatting, lint, type, unit, contract, integration, security, recovery, and acceptance checks as applicable.
14. Independently verify the result.
15. Repair through bounded reapproval when material scope changes.
16. Preserve evidence, limitations, registry updates, and rollback.
17. Stage, commit, push, review, merge, and deploy only through separately approved protected actions.
18. Verify remote equality, cleanup, resource termination, and the applicable completion gate.
19. Recommend the next compounding capability without activating it silently.

## Stop Conditions

Stop before implementation when governance is missing, sources conflict, license or security is unresolved, protected approval is absent, scope cannot be bounded, rollback is unavailable, or verification cannot be made credible.
