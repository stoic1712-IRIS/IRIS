# Governed Complex Worker Development

**State:** Local implementation and fictional verification in progress

## Objective

Extend the proven read-only worker lifecycle with one exact, disposable, Founder-approved coding-worker execution and an evidence-based learning proposal.

## Authority Contract

- Coding workers require an immutable worker digest, exact typed Founder approval, expiry, bounded write paths, fixed verification commands, a 2,000-line ceiling, and USD 0 cost.
- Workers receive no canonical working-tree, GitHub provider, credential, network, delegation, self-approval, permission-expansion, merge, or deployment authority.
- A writable runtime must still be disposable; read-only and coding workspace modes cannot be substituted.
- Reported paths must remain inside the union of approved read and write paths.
- Termination and verified cleanup remain mandatory after success, failure, timeout, or revocation.

## Learning Contract

Worker outcomes become evidence-bound evaluation proposals containing passed checks, failed checks, Founder feedback, and evidence digests. Evaluations remain `pending-founder-approval` and cannot mutate canonical memory automatically.

## Acceptance

One fictional coding worker must be denied before approval, succeed after an exact matching approval, stay within one approved file, produce required verification output, terminate, clean its workspace, and emit a noncanonical learning proposal. A later real-model and real-repository activation requires a separate exact R3 proposal.
