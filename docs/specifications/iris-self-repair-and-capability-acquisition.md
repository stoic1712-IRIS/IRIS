# IRIS Self-Repair and Capability Acquisition

**Status:** Implemented Core contract; provider-bound execution requires an exact adapter and proposal

**Owner:** IRIS Core

## Capability package map

1. **Objective:** replace generic inability responses with exact diagnosis, repair, or acquisition.
2. **Owner/classification:** permanent IRIS Core capability; the Command Center is a consumer.
3. **Graph:** operator preflight → gap classifier → acquisition proposal → self-repair runtime → delivery adapter → registry → resumed objective.
4. **Prerequisites:** canonical governance, Full-access contract, research integrity, complete delivery, model routing, and disposable workspaces.
5. **Tools/sources:** official or primary HTTPS sources, pinned versions, SHA-256, license and removal evidence.
6. **Candidates:** provider identity is proposal data; no default provider is silently adopted.
7. **Reviews:** cost, permissions, data exposure, portability, rollback, and removal are mandatory.
8. **Boundary:** models and browser content may suggest evidence but cannot authorize or execute installation.
9. **Location:** `packages/capabilities` and `packages/development`.
10. **Tasks:** classify, prepare, approve, acquire in a disposable workspace, verify, register, resume, clean.
11. **Contracts:** ten strict gap types, digest-bound acquisition proposal, hash-linked self-repair events.
12. **Verification:** schema, replay, expiry, tamper, protected-stop, cleanup, and resume-binding tests.
13. **Recovery:** cancellation and failure enter `recovery-ready`; any created workspace must be cleaned.
14. **Diagnostics:** exact missing capability, evidence, state, proposal, and cleanup status.
15. **Registries:** update only after verification and through the exact approved proposal.
16. **Gate:** verification, independent review where available, registry revision, objective resume, and cleanup.
17. **Unlocked capability:** governed learning and repair without silent authority expansion.
18. **Future owner:** IRIS Core; external providers remain replaceable.
19. **Layer 4 reuse:** applications consume the Core state and approval contracts without owning them.

## Ordinary and protected split

Gap classification and source research are read-only. A zero-dollar, non-elevated acquisition may proceed only through an exact, unexpired, digest-bound plan under active Founder Full access. Credentials, spending, elevation, deployment, exposure, administration, destructive work, or scope changes stop for separate approval.

The self-repair sequence is observe, reproduce, diagnose, propose, approve, acquire in a disposable workspace, verify, register, resume the exact original objective, and clean. Objective, model policy, acquisition digest, verification evidence, and registry revision remain bound across resume.

This machinery is not evidence that IRIS completed the separate real canonical self-upgrade required for Phase 0 graduation.
