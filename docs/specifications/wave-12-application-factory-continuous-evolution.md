# Wave 12 Application Factory and Continuous Evolution

**Status:** Implemented and locally verified

**Date:** 2026-08-05

## Purpose

Wave 12 converts an exact Founder-owned application specification and approved capability selection into a non-executable Layer 4 application proposal. It also converts research and benchmark evidence into governed evolution proposals. Neither engine grants itself authority.

## Application Factory

The factory requires a strict Layer 4 specification, a separate repository, and a capability selection bound to the exact specification digest and approved by the Founder. Every selected capability records source, version, license, license approval, and security approval.

The generated bundle proposes a private repository outside IRIS Core, exact digest-bound files, a portable infrastructure blueprint, verification and security checks, license review evidence, disposable deployment commands, rollback and cleanup, provider-zero verification, and maintenance and monitoring plans. Repository creation and deployment remain unexecuted protected actions.

## Continuous Evolution

Research intake records source identity, revision, license, observation time, and bounded claims. Benchmarks record subject, metric, value, unit, environment, and evidence digest. Architecture comparisons, upgrades, deprecations, native replacements, roadmap reprioritization, and self-improvement are emitted only as `pending-founder-approval` proposals with `executionAuthorized: false`.

## Layer 4 Boundary

Generated application code never enters the IRIS Core repository as a product. Only reusable factory contracts, tests, specifications, and evidence live here. A generated application must use a separate private repository. IRIS may propose its creation and contents but may not create, merge, deploy, expose, spend, or use credentials without the corresponding exact protected approval.

## Acceptance

Acceptance requires rejection of altered capability approvals, private separate-repository planning, a valid locked infrastructure blueprint, exact generated-file digests, disposable workspace materialization and verified removal, security/license/test/build plans, rollback and provider-zero plans, maintenance and monitoring plans, all six continuous-evolution proposal categories, evidence requirements, and the full repository verification suite.
